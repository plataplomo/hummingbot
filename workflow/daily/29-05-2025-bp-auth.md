# TASK (S5 - DEFINITIVE): Implement Unified Backpack ED25519 Authenticator & Correct Generic API Integration

## 1. Goal
Implement the complete, correct, and architecturally sound ED25519 authentication mechanism for all Backpack signed operations (REST API requests and WebSocket private stream subscriptions). This solution ensures base API layers remain generic, and all Backpack-specific authentication logic is encapsulated within `BackpackEd25519Authenticator`.

**Key Implementation Steps:**
1.  **Update Base Authentication Interface (`authenticator_interface.py`):**
    a.  Ensure `AuthenticatedRequestComponents` is a Pydantic `BaseModel`.
    b.  Ensure `IAuthenticator.prepare_request` signature is generic: `async def prepare_request(self, method: str, path: str, params: dict | None, data: dict | None, headers: Mapping | None) -> AuthenticatedRequestComponents`. (No `auth_context`).
2.  **Verify `HttpClient.request` (`http_client.py`):**
    a.  Ensure it calls `authenticator.prepare_request` with the standard generic signature when `is_signed=True` and an `authenticator` is provided. (No `auth_kwargs`).
3.  **Refactor `ExchangeAPI` Base Class (`exchange_api.py`):**
    a.  **Remove the `_authenticate` abstract method and any calls to it within `ExchangeAPI._request`.**
    b.  `ExchangeAPI._request` will now directly pass `is_signed` and `self._authenticator` to `self._http_client.request`. `HttpClient` will be solely responsible for invoking `authenticator.prepare_request` if needed.
4.  **Implement `BackpackEd25519Authenticator(IAuthenticator)` (in `bp_auth.py`):**
    a.  `__init__`: Takes Base64 public & private keys (for `cryptography` library) and initializes an internal `INSTRUCTION_MAP` mapping `(HTTP_METHOD_UPPER, relative_path_template)` to `instruction_string`.
    b.  `prepare_request(...)`: Implements the full ED25519 signing for REST. It will internally:
        i.  Determine the `instruction` string using the input `method` and `path` against its `INSTRUCTION_MAP`. This may require logic to match variable path segments (e.g., `/api/v1/order/{order_id}`).
        ii. Construct the full signable string (instruction, sorted params/body, timestamp, window).
        iii.Sign and return `AuthenticatedRequestComponents` (Pydantic model) with `X-` headers.
    c.  `get_ws_subscription_signature_tuple(...)`: Dedicated helper method to generate the 4-element tuple for WS `signature` array.
5.  **Refactor `BackpackAPI` (in `bp_api.py`):**
    a.  **Remove its override of `_request` and `_authenticate` (if they existed for auth purposes).** It will use the generic `ExchangeAPI._request`. Signed calls from its service methods will now correctly flow through `ExchangeAPI._request` -> `HttpClient.request` -> `BackpackEd25519Authenticator.prepare_request`.
    b.  `_construct_subscription_payload`: Calls `self._bp_authenticator.get_ws_subscription_signature_tuple()` for private streams and passes the signature components to `self._bp_ws_router.construct_subscription_payload()`.
6.  **Refactor `BackpackWsMessageRouter` (in `bp_ws_message_router.py`):**
    a.  `__init__`: Does **not** need the authenticator instance.
    b.  `construct_subscription_payload`: Now takes an optional `signature_components_tuple: tuple[str, str, str, str] | None` as an argument and uses it to populate the `signature` field of `BackpackRawWsSubscriptionRequest`.
7.  **Update `BackpackAPIComponentsFactory`:** To instantiate `BackpackEd25519Authenticator`.

## 2. Context and "Why"
This is the definitive approach to Backpack ED25519 authentication. It strictly encapsulates all Backpack-specific logic (including `instruction` derivation for REST) within `BackpackEd25519Authenticator.prepare_request`. The base layers (`ExchangeAPI`, `HttpClient`, `IAuthenticator`) remain truly generic, fulfilling a core architectural requirement. `HttpClient` universally calls `authenticator.prepare_request` for all signed REST requests.

### Part C: Implement `BackpackEd25519Authenticator`

**File:** `cyberdelta/apis/backpack/bp_auth.py`

1.  **Create `BackpackEd25519Authenticator(IAuthenticator)`**.
2.  **Imports:** (As detailed in previous valid prompts for this class).
3.  **`__init__(...)`:**
    *   Stores Base64 public key (`self._api_key_b64`).
    *   Initializes `self._ed25519_private_key` using `cryptography`.
    *   **Define and store `self.INSTRUCTION_MAP: dict[tuple[str, str], str]`**.
        *   Keys are `(HTTP_METHOD_UPPER, relative_path_template_str)`.
        *   Values are `instruction_str`.
        *   Example: `self.INSTRUCTION_MAP = {("POST", "/api/v1/order"): "orderExecute", ...}`.
        *   This map is crucial for `prepare_request`. You will need a robust way to match an incoming `path` (e.g., `/api/v1/order/12345`) to a path template (e.g., `/api/v1/order/{orderId}`). Simple string matching might work for paths without variables. For paths *with* variables, you might need to iterate map keys and use regex or string splitting. Start with exact matches for paths without variables.
4.  **`async def prepare_request(self, method: str, path: str, params: dict | None, data: dict | None, headers: Mapping | None) -> AuthenticatedRequestComponents:`** (Implements `IAuthenticator`)
    *   **Logic:**
        a.  **Determine `instruction_str`:**
            *   Look up `(method.upper(), path)` in `self.INSTRUCTION_MAP`.
            *   If not found directly, implement logic to match `path` against templates in `INSTRUCTION_MAP` keys (e.g., by stripping trailing IDs if path matches a template like `/api/v1/order/{id}`). This is the most complex part here. If a robust match isn't found, `raise APIError(f"Backpack instruction not found for {method} {path}", code=APIErrorCode.INVALID_REQUEST.value)`.
        b.  Generate `timestamp_ms`, `window_ms`.
        c.  Construct `content_part_str` from `params` (for GET) or `data` (for POST/PUT/DELETE - `data` input here is already a `dict`). Remember to filter `None` values *before* sorting and urlencoding.
        d.  Construct `string_to_sign`.
        e.  Sign -> `signature_b64`.
        f.  Create `auth_only_headers` with all `X-` auth fields.
        g.  `final_headers = (headers or {}).copy()`. Add `Content-Type` if needed. `final_headers.update(auth_only_headers)`. Stringify.
        h.  Return `AuthenticatedRequestComponents(headers=final_headers, params=params, data=data)`.
5.  **`get_ws_subscription_signature_tuple(...)`:** (As previously well-defined).
