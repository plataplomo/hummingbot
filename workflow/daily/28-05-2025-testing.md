
The `__init__` signatures of `BackpackAPI`, `HyperliquidAPI`, their component factories, and `BackpackRequestBuilder` have changed from accepting generic `dict`s for configuration and secrets to accepting specific Pydantic model instances (`ExchangeSpecificConfig`, `ExchangeSecrets`).

This means any test that instantiates these classes will now fail due to `TypeError` if not updated.

Here's the strategy and prompt for Angel to update the tests:

**Strategy for Updating Tests:**

1.  **Identify Affected Tests:** Angel needs to locate all test files and methods where the refactored classes are instantiated.
2.  **Create Mock Pydantic Instances:** For each test setup, Angel will need to create minimal, valid instances of `ExchangeSpecificConfig` and `ExchangeSecrets` (the sub-model within `ExchangeSecretsConfig`).
3.  **Update Instantiation Calls:** Replace the old dictionary-based `api_config` and `secrets` arguments with these new Pydantic model instances.
4.  **Handle `chain_id` for Hyperliquid:** Tests involving Hyperliquid components must provide an `ExchangeSpecificConfig` instance with `chain_id` populated.
5.  **Address `super().__init__` Changes:** If tests mock or assert on the `config` or `secrets` dicts passed to `ExchangeAPI.__init__`, they need to be updated to reflect the new structure of these dicts (e.g., `config` now containing `rate_limits` sub-dict and optional HTTP/WS params; `secrets` being a flat dict of secret values).
6.  **`HttpClientConfig`/`WebSocketManagerConfig` in `ExchangeAPI`:** If tests relied on specific values being passed through the old `api_config` to influence the creation of `HttpClientConfig` or `WebSocketManagerConfig` within `ExchangeAPI`, these tests now need to ensure those values are set on the mock `ExchangeSpecificConfig` instance.

## 1. Goal
Update all affected unit tests across the project to correctly instantiate `BackpackAPI`, `HyperliquidAPI`, their respective component factories (`BackpackAPIComponentsFactory`, `HyperliquidAPIComponentsFactory`), and `BackpackRequestBuilder`. These classes now expect Pydantic models (`ExchangeSpecificConfig` and `ExchangeSecrets`) in their constructors instead of generic dictionaries for `api_config` and `secrets`. The goal is to make all existing tests pass with these new signatures.

## 2. Context and "Why"
The API client layer has been refactored to use Pydantic models for configuration and secrets, enhancing type safety and maintainability. Unit tests that instantiate these refactored classes must be updated to provide these Pydantic model instances, ensuring the test suite remains valid and accurately reflects the new codebase structure.

## 3. Affected Classes (Summary of `__init__` changes)
- `BackpackAPI(exchange_config: ExchangeSpecificConfig, exchange_secrets: ExchangeSecrets, ...)`
- `BackpackAPIComponentsFactory(exchange_config: ExchangeSpecificConfig, exchange_secrets: ExchangeSecrets)`
- `BackpackRequestBuilder(exchange_config: ExchangeSpecificConfig)`

### 5.3. Specific Considerations for `ExchangeAPI` Base Class
   - Some tests might indirectly test the `ExchangeAPI.__init__` method by instantiating `BackpackAPI` or `HyperliquidAPI`.
   - The `config` dictionary passed to `super().__init__(..., config=config_dict_for_super, ...)` has changed:

     - It includes optional keys like `request_timeout`, `ws_ping_interval`, etc., derived from `ExchangeSpecificConfig`.
     - `rate_limits` is a nested dictionary: `{"default_rate": ..., "default_bucket_size": ...}`.
   - The `secrets` dictionary passed to `super().__init__` is now a flat dictionary of specific secret strings (e.g., `{"BACKPACK_API_KEY": "...", "private_key": "..."}`).
   - If any tests mock the `config` or `secrets` dict received by `ExchangeAPI`, they must be updated to reflect these new structures.

### 5.4. Handling `HttpClientConfig` and `WebSocketManagerConfig`
   - `ExchangeAPI.__init__` now constructs `HttpClientConfig` and `WebSocketManagerConfig` using values from the `config` dict (which was derived from `ExchangeSpecificConfig`).
   - If a test was verifying that, for example, a specific `request_timeout` from the old `api_config` dict was being used, that test should now ensure the `mock_exchange_config.request_timeout_seconds` is set and that it correctly flows into the `HttpClientConfig`.
